# HW2 設計說明與實測數據

環境建置與執行步驟請見 [README.md](README.md)。本文件說明作法、查詢前處理規則，以及以 HW1 索引 `HW1.txt`（ClueWeb09 的 `02.warc`，35,011 篇文件、502,131 個詞）實測的結果。

---

## 1. 作法概述

純 Python 實作**向量空間模型**，直接讀取 HW1 的倒排索引，不需要 Solr。

```
查詢 → 查詢前處理 → 解析查詢 → 篩選候選文件 → 計分並排序 → 輸出前 N 名
      (analyzer.py)  (布林/片語/萬用字元)  (集合運算、位置比對)  (TF-IDF + cosine)
```

**計分**（作業指定）：`w = (1 + log tf) × log(N/df)`，查詢向量與文件向量做 cosine similarity。

**輸出格式**：

```
Query: hong kong business
clueweb09-en0000-02-10187    0.223081
clueweb09-en0000-02-23014    0.205800
...
```

每行 `<doc#> <similarity score>`，由高到低。文件編號用索引裡的 `WARC-TREC-ID`。互動模式印在畫面，批次模式 (`--queries`) 寫成輸出檔。

## 2. 功能特色

### 2.1 查詢功能（可互相組合，例如 `"open source" AND linux`）

| 類別 | 範例 | 說明 |
|---|---|---|
| 單一關鍵字、自由文本 | `airplanes`、`United States government` | 作業基本要求 |
| 布林查詢 | `hong AND NOT kong`、`(arc OR zip) AND stop` | `AND`、`OR`、`NOT`、括號 |
| 片語 | `"hong kong"` | 詞依序緊鄰，利用索引的位置資訊 |
| 鄰近 | `"hong kong"~5` | 所有詞在 5 個位置內，不限順序 |
| 萬用字元 | `govern*`、`*ment`、`micro*soft` | `*` 代表任意長度字元 |
| 子字串 | `*ernmen*` | 兩邊都放 `*`，找出含該字串的詞 |
| 拼字校正 | `goverment` → `govern` | 編輯距離（含相鄰字母對調） |
| 發音校正 | `smyth` → `smith`、`mikrosoft` → `microsoft` | Soundex 同音詞 |

### 2.2 三種權重方案的實測對照（`--weighting`）

| 方案 | 文件詞權重 | 排序 |
|---|---|---|
| `tfidf`（預設） | `(1 + log tf) × log(N/df)` | cosine similarity（0 到 1） |
| `tfidf-raw` | `tf × log(N/df)` | cosine similarity |
| `bm25` | Okapi BM25（`k1=1.2`、`b=0.75`） | 直接加總，分數可大於 1 |

同一查詢，各方案前 10 名與 `tfidf` 前 10 名重疊的篇數：

| 查詢 | tfidf-raw | bm25 |
|---|---|---|
| `airplanes` | 4 | 4 |
| `hong kong business` | 2 | 1 |
| `"open source" AND linux` | 0 | 8 |

三種方案的排名差異明顯。BM25 分數與作業範例（小於 1）尺度不同，所以預設用 `tfidf`。

### 2.3 網頁介面與查詢詞標示

`python SourceCode/WebApp.py` 啟動網頁介面（標準函式庫的 `http.server`，無額外套件）：搜尋框、權重方案與筆數選單、拼字建議連結、結果摘要與全文頁。查詢詞用和索引相同的分析鏈（`token_spans`）還原詞幹後比對，所以搜尋 `airplanes` 時文中的 `airplane`、`Airplanes` 都會被標示。摘要取查詢詞最密集的一段約 300 字。

### 2.4 其他

- **效能**：載入索引約 13 至 20 秒（視機器負載），之後一般查詢約 0.01 秒，片語約 0.03 秒，以 `*` 開頭的萬用字元約 0.15 秒（要掃整個詞典）。
- **位置資訊不佔記憶體**：載入時只記每個詞在檔案中的位元組位置，片語與鄰近查詢才回頭讀候選文件的位置。
- **文件向量長度在載入時預先算好**，查詢時不必重算。
- **批次輸出檔**：每個查詢一段，`#` 開頭的行是註解（錯誤訊息、拼字建議、萬用字元展開說明）。

## 3. 查詢前處理方式

查詢要和 HW1 的索引用**同一條分析鏈**才對得上：切詞 → 小寫 → 停用詞（35 個，與 HW1 相同）→ Porter 詞幹還原。例如 `governments` 會變成索引裡的 `govern`。

**斷詞**：用規則式重現 HW1 的 Solr StandardTokenizer（Unicode 標準的斷詞規則）。實測：

| 類型 | 輸入 | 切出的詞 |
|---|---|---|
| 標點符號 | `cats, running!` | `cat`、`run` |
| 連字號 | `State-of-the-art` | `state`、`art`（其餘是停用詞） |
| 日期 | `2005-09-12` | `2005`、`09`、`12`（切開） |
| 小數、千分位 | `3.14`、`1,000` | 整個保留 |
| 縮寫 | `don't` | 整個保留 |
| 網域 | `www.amazon.de` | 整個保留 |
| 底線 | `user_id` | 整個保留 |
| 字母間的逗號 | `hello,world` | `hello`、`world`（切開） |
| Email | `E-mail` | `e`、`mail`（切開） |

與 HW1 的斷詞表一致。

**位置（positions）**：停用詞**不會重新編號**，會留下空位，與 HW1 索引相同。所以 `"united states of america"` 中 `america` 的位置是 3，`of` 的空位可由任何停用詞佔據。

## 4. 遇到的困難與解法

1. **索引存詞幹，但查詢是使用者打的原字。** 一開始只做小寫與空白切詞，查 `governments`、`airplanes` 找不到。寫 `analyzer.py` 重現 HW1 的分析鏈，並用索引驗證（`govern`、`organ`、`airplan` 等都對得上）。
2. **查詢端的斷詞規則和 HW1 不一致。** 第一版的規則會把 `user_id` 切成 `user` 與 `_id`，也會把 `hello,world` 連成一個詞。我們用整個索引做檢查（索引裡的詞經過查詢斷詞後不該被切開）：舊規則切壞 24,340 個詞，修正後降到 14,763 個（占 502,131 個詞的 2.9%）。剩下的多是所有格詞幹（`10th's` 經 Porter 變成 `10th'`）與非英文的組合符號，不是斷詞錯誤。
3. **片語與鄰近查詢需要位置資訊，但全部載入記憶體太大。** 索引檔約 457 MB。改成只記位元組位置，查詢時才讀。並拿原始 WARC 文字對照：`"hong kong"` 的 560 篇結果中 559 篇在原文也有連續出現。
4. **拼字校正被詞幹與雜訊詞干擾。** 拼錯的 `goverment` 還原成 `gover`，剛好是索引裡一個 df=30 的雜訊詞，所以不會被判為拼錯。解法：把 df 很低（小於 50）的詞也視為可疑，若有編輯距離 1 且 df 高 20 倍以上的相近詞就建議（得到 `govern`）。
5. **champion list 第一版品質很差。** 照課本用 tf 最高者挑選，R=200 時前 10 名重疊率只有 17%（見第 5 節）。
6. **萬用字元可能展開成數萬個詞。** 樣式至少 2 個非 `*` 字元，展開結果只保留 df 最高的 50 個，被截斷時會顯示說明。

## 5. Champion list 近似 top-k（選做）

`--champion R`：啟動時為每個 df 大於 R 的詞建立 champion list，只保留「對該詞貢獻最大」的 R 篇文件，查詢時只掃這份清單。結果少於 `--top` 篇時，自動退回掃完整 postings。布林、片語、萬用字元的文件篩選仍然精確，只有計分是近似。

**挑選方式**：第一版照課本用 tf 最高者，但 tf 最高的常是長文件，而 cosine 與 BM25 會做長度正規化，真正排前面的是短文件，所以前 10 名重疊率很低。改成依「該權重方案下的貢獻（含長度正規化）」挑選後，品質大幅提升。

`python SourceCode/Benchmark.py` 實測（12 個查詢，只量計分與排序；重疊 = 與精確計分前 10 名相同的比例）：

| 方案 | R | 平均耗時 | 加速 | 前 10 名重疊 |
|---|---|---|---|---|
| tfidf | 精確 | 10.01 ms | 1x | 100% |
| tfidf（第一版：只用 tf 挑選） | 200 | 0.23 ms | 41x | 17% |
| tfidf | 50 | 0.05 ms | 186x | 66% |
| tfidf | 200 | 0.22 ms | 45x | 92% |
| tfidf | 1000 | 1.10 ms | 9x | 98% |
| bm25 | 精確 | 9.77 ms | 1x | 100% |
| bm25 | 200 | 0.23 ms | 43x | 70% |
| bm25 | 1000 | 1.38 ms | 7x | 93% |

R 越小越快、越不準；`tfidf` 用 R=200 是不錯的折衷，BM25 要 R=1000 才接近。啟用後畫面顯示的命中篇數會比精確模式少，前幾名大致相同。耗時隨機器而異。

## 6. 已知限制

- 索引存的是詞幹，所以拼字與發音建議、萬用字元比對的都是詞幹形式（`air*ne` 找不到 `airplane`，要用 `airpl*`）。
- 索引裡有 HW1 切詞留下的雜訊詞（如 `government'`、`state.edu`）。
- Soundex 只適合英文，輸入僅限文字。
- 網頁介面 (`WebApp.py`) 的摘要與全文需要 HW1 的 WARC 檔；標示查詢詞是依詞幹比對，片語查詢會標示每個詞，不只標示連續出現的片語。
